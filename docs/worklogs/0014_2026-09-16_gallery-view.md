# 0014 — Gallery view: browse every published track

**Date:** 2026-09-16
**Triggered by:** Owner spec — a 🌍 Gallery beside "My published tracks"
that browses ALL tracks on the server (not just this browser's), so
people can find and load tracks. "Sort by track distance, lanes, total
dimensions (e.g. if they have limited room)"; complete-only filter;
stars; tap-to-load.

---

## What shipped

- **Menu + dialog.** Track menu gains "🌍 Gallery" next to "My published
  tracks". The dialog reuses the dark dialog patterns (`.dialog-head`,
  `.io-hint`, chip buttons like `.mode-switch`); glyph-only icons (no
  icon library — the MDI conversion is a separate planned PR).
- **Sorts** (server-side, the facet API from `feat/gallery-facets`):
  Newest (`-updated_at`), Length (`-length`), Lanes, Footprint
  (`-bbox`, bbox area — the room-limited case), Stars, Straights,
  Corners. Horizontally scrollable chip row, `aria-pressed` state, like
  the palette.
- **Filter:** "✓ Complete only" toggle → `complete=true` (the
  server-validated facet, not browser opinion).
- **Rows** show name, ✓/✖ badge (amber ✖ carries the server's issue
  count for WIP), pieces, length, lanes, footprint (cm under a meter, m
  above), straights/corners counts, ★ count, updated date.
- **Stars:** ☆/★ button per row POSTs `/api/tracks/:id/star`; the
  per-browser de-dupe lives in localStorage (`m4wd.starred`) — one star
  per browser per track, button reflects the stored state across
  reopens. No auth exists; that's accepted.
- **Load:** tapping a row reuses the library flow (now the shared
  `loadPublishedTrack`): GET `/api/tracks/:id`, confirm-replace when the
  canvas holds work, `bindPublished(row)`, `loadSprites`, `fitView`,
  toast. A gallery load adopts the publication binding — edits
  auto-save from there.
- **Pagination:** "Load more" button; pages of 25 via `limit`/`offset`
  (`x of N tracks` meta line).

## Structure

- `src/gallery.js` (new, pure): sort table, list-query builder, badge/
  footprint formatters, star de-dupe. Unit-tested in isolation.
- `src/ui.js`: gallery DOM wiring inside `init()`; `loadLibraryTrack`
  renamed `loadPublishedTrack` and shared by library + gallery.
- Server fix (in-scope dependency): the memory driver never initialized
  `stars` — the first star returned `null` and `-stars` sorted nothing.
  `upsert` now seeds `stars: prev ? prev.stars : 0`, matching the
  sqlite/pg column default and their "re-saves never reset stars"
  behavior. Pinned for every driver in the shared conformance suite.

## Tests

- Unit: 6 gallery tests (sort values all accepted by the API's sort
  whitelist — a rename on either side fails the test; query shape;
  footprint unit switch; badge states; starred round-trip + corrupt/
  private-mode storage never throws) + the store-conformance stars test
  (fails on pre-fix memory driver: stars `undefined` → `null`).
- E2E (`tests/e2e/gallery.spec.js`, serial mode — the pagination test
  floods 26 rows that would push fresh rows off page 1 for the other
  tests): rows render with facets, Length sort reorders, complete-only
  filter hides WIP, star increments the server counter exactly once and
  survives reopen, row tap loads 4 sprites + adopts the binding (💾),
  Load more pages without skips.

## Review round additions

- `galLoad` gained an in-flight guard (`loading` lock + monotonic `gen`):
  a double-tap on Load more no longer fetches the page twice (the
  offset was computed before either fetch resolved → duplicated page,
  inflated "x of N"), and a page superseded by a sort/filter switch is
  dropped instead of appended into the new view. A dropped page leaves
  the lock alone — the newer call owns it. Pinned by an e2e that
  dblclicks Load more and asserts every row name is unique.
- The facets commit had left sqlite.js's `COLS`/`SORTS` constants
  inside `open()`'s body (function-local, unindented — a diff
  artifact); moved back to module level matching pg.js.
- Busters bumped again for the ui change: main.js `?v=57`, BUSTER 29.
