# 0016 — MDI icons + product framing

**Date:** 2026-09-16
**Triggered by:** Owner — "mdi has a save icon with a check mark. Should we
use mdi instead of emojis?" then "rewrite the readme — this isn't a PoC
anymore... focus on the features and experience."

## Icons

26 Material Design Icons path strings vendored into `src/icons.js` (MIT,
© 2014-2025 Austin Andrews, credited inline) — path data only, no font, no
CDN: CSP-safe and dependency-free (the app import graph stays zero-dep).
Static buttons carry `data-icon` spans hydrated once at init; the
publish/save badge swaps `cloud-upload` ↔ `content-save-check` (the owner's
pick) via `icon()`. Emojis are gone from the chrome (toolbar, menus,
dialogs, zoom controls); emoji/text inside sentences (toasts, help copy)
became plain words where they referenced glyphs. Specs asserting emoji
glyph text on the badge now assert the SVG path.

## Framing

README rewritten features-and-experience first (editor, validation,
publishing/gallery, running it) with a short dev section; the fork/PoC
comparison tables and parity roadmap are gone — attribution stays in
Credits (Pimentoso/rucdoc/Tamiya/MDI). index.html title/description/menu
credits and main.js header de-PoC'd the same way; help-copy glyph
references became tool names.
