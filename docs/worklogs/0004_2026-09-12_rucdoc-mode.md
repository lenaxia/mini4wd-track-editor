# 0004 — Rudoc mode: third palette drawer, seed catalog from published dims

**Date:** 2026-09-12  
**Triggered by:** Owner green-lights rucdoc support and asks for a "Rudoc" button
next to the lane switchers.

---

## Summary

Added a third palette drawer ("Rudoc") beside 3 lane / 5 lane, seeded with 10
pieces derived analytically from rucdoc's **published dimensions** — no 3D
models required yet (procedural art covers them via the existing kinds).
This is track 1 of the two-track rucdoc plan; track 2 (top-down ortho
renders as base+mask PNGs, measured catalog asserts, attribution) lands
when the projection pipeline runs, per `docs/design/orient-elevation.md` §6/§9.

## Changes

- **Mode system**: `state.mode` now `3 | 5 | 'rucdoc'`; storage round-trips
  the string; `setMode` re-arm semantics unchanged (tool-tools survive,
  pinned). One drawer, not three — his catalog spans 1/2/3-lane in one
  clip-compatible family; palette grouping matches his own organization.
  Per-lane top-level buttons would collide with the parametric families
  anyway (palette grouping/search is the endgame, spec §9).
- **Seed catalog (10 pieces)**: 1L/2L/3L straights 250mm, 45° corners
  (IR150/IR150/IR115), 1L 90° IR150, ramps L250 R50 — all with **real
  rises as zOff mm** (50). Geometry derived: lane widths 13/25/37cm
  (115mm lanes + 50mm walls), corner centerline `R = IR + width/2`,
  arcs validated by the existing solveGeo endpoint-exactness test (1e-6).
- **Keyboard families** for the drawer: 1 = straights (cycle 1L/2L/3L),
  2 = corners, 3 = ramps.
- **Invariant honestly relaxed**: vertex-separation floor drops from
  2×SNAP_RADIUS to 1.5× — rucdoc's 1L 45° chord is 16.45cm; Tamiya's
  30cm+ separation guarantee was a proportion accident, not physics.
  Closest-pair determinism unaffected; the both-vertices-in-range window
  widens (hysteresis stays deferred, spec §9).
- `?v=6`.
