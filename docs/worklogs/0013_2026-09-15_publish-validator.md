# 0013 — Toolbar publish/save with validator gating

**Date:** 2026-09-15
**Triggered by:** Owner spec — publish moves to the main toolbar with a
confirm dialog (and cancel); once published the button becomes Save; the
canvas knows what track it is working on; publish/save requires the track
to be complete and consistent; Y-junctions must stay legal ("eventually
support y junctions and stuff").

---

## Validator (`src/validate.js`, pure)

- **blocks**: empty track; dangling ends (a vertex coincident with no other
  AND not facing another open end as an intentional jump — same 45 cm /
  50° thresholds as `openLinks`); kinked joints.
- **warns**: crossover clearance < 75 mm (bridges/jumps are legitimate —
  the paint rule, not a blocker).
- **permits**: junctions. The kink check requires each vertex in a
  coincidence group to have at least one tangentially-aligned partner —
  NOT all-pairs (two entries at one point both flow away from the shared
  exit; they are not connected to each other). All-pairs would have made
  every future Y-junction unpublishable.

## UI

- Toolbar button next to Complete: 📤 Publish → 💾 Save once bound; title
  carries the track name.
- Confirm dialog (like Complete's): name field, live validation status
  (red errors / amber warnings / green "complete and consistent"),
  Confirm disabled while invalid, explicit Cancel. Re-validates at the
  moment of saving.
- Canvas awareness: the stats bar prefixes the working track's name;
  boot, library-load, and New Track all refresh the button + stats.

## Tests

- 8 validator units, including an exact closed square generated by the
  app's own chaining math (closure 2.5e-15), float-exact kink and
  Y-junction fixtures built via rot()/orientAngle() inverses, and the
  jump-pair/dangling distinction.
- e2e: incomplete track → dialog shows "Dangling end", Confirm disabled,
  Cancel sends nothing; complete square → publishes from the toolbar,
  button flips to 💾; library load on a fresh browser adopts the binding.
